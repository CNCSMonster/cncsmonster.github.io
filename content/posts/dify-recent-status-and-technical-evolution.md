## 一、 一个体感：为什么我觉得它"很久没消息了"？

至少在我自己的圈子里，2024 年下半年到 2026 年间，确实很少再看到有人讨论 Dify 了。第一反应是：是不是被淘汰了？

但翻了一圈资料之后，我发现这种"失踪感"可能更多来自**我们自己的注意力转移**，以及 **Dify 自身的战略位移**：

```
2023 ~ 2024 上半年 (极客狂欢期)                 2025 ~ 2026 (分化期)
[个人开发者 / 提示词工程师]                    [代码优先派 (极客/后端)]
      │                                                │
      ▼                                                ▼
热衷 GUI 拖拽搭 Bot / 简单知识库           转向 Coding Agent (Cursor/Claude Code)
Dify、FastGPT 社媒刷屏                     转向代码级状态机 (LangGraph/PydanticAI)
                                               
                                               [Dify 真实位移路径]
                                                       │
                                                       ▼
                                           出海国际化 (日本/北美/欧洲)
                                           深水区 ToB (企业合规/私有部署/跨国巨头)
```

### 1. 极客圈的注意力转向

* 2023 到 2024 年初，大模型生态还在摸索"怎么把模型连上知识库和提示词"，可视化 DAG 拖拽是当时门槛最低、演示最直观的形式；
* 后来技术圈的注意力明显转向了 **Coding Agent**（Cursor、Claude Code 等）和**代码优先的状态机框架**（LangGraph、PydanticAI 等）。代码形态下 Git 管理、单元测试更原生，社媒上晒"连线图"的人自然就少了。

### 2. Dify 自己的重心转移

* 从公开信息来看，LangGenius 团队主动降低了国内极客营销的声量，把精力投向了海外市场与大型企业客户；
* 增长最快的市场在**海外（尤其是日本与北美）**。国内社媒讨论降温的同时，Dify 在日本办了数百人线下峰会、进驻了 AWS 官方渠道，并在跨国企业内网完成了私有化落地。

## 三、 产品与技术演进（v0.x 到 v1.17+）

从版本迭代来看，Dify 的产品形态已经明显超出了早期"可视化调 Prompt"的阶段，底层技术栈经历了多次重构：

```
                    ┌─────────────────────────────────┐
                    │       Dify Marketplace          │ (插件生态/社区资产)
                    └────────────────┬────────────────┘
                                     │
┌───────────────────────────────┐    │    ┌───────────────────────────────┐
│        New Agent App          │    │    │       Workflow Studio         │
│ (自主推理/Skills/代码沙箱)   │◄───┴───►│ (可视化编排/分支合并/动态路由)│
└───────────────┬───────────────┘         └───────────────┬───────────────┘
                │                                         │
                └───────────────────┬─────────────────────┘
                                    ▼
       ┌────────────────────────────────────────────────────────┐
       │   MCP Gateway (Workflow-as-MCP-Server / ClientPassthru)│
       └────────────────────────────┬───────────────────────────┘
                                    ▼
       ┌────────────────────────────────────────────────────────┐
       │     Core Engine (异步非阻塞引擎 / 沙箱隔离 / RBAC)      │
       └────────────────────────────────────────────────────────┘
```

### 1. 全面接入 MCP（Model Context Protocol）协议

* **Workflow-as-MCP-Server**：用户在 Dify 内部编排的复杂业务工作流，可以直接一键作为标准的 MCP Server 对外暴露。无论是 Claude Desktop、IDE 还是外部 Coding Agent，都可以把 Dify 工作流当作标准 MCP 工具直接调用；
* **运行时动态 Header 透传**：支持在请求阶段动态注入占位符鉴权（如 `{{request.headers.X-Custom-Auth}}`），解决了企业多租户在调用第三方工具时的安全隔离与身份鉴权难题。

### 2. 插件体系（Plugin System）与 Marketplace 彻底解耦

* **告别源码魔改**：在早期的 v0.x 时代，社区开发者想接入一个新的模型或私有内部系统，往往需要 fork 仓库、修改核心代码甚至自己维护版本。v1.0（2025 年初）重构了插件架构，工具、模型完全解耦为独立插件运行；
* **Marketplace 与插件安全治理**：引入了插件安全级别（Security Level）、签名验证与沙箱隔离，企业用户可在内网部署私有插件源，兼顾扩展性与合规性。

### 3. Agent 架构重构：New Agent App 与沙箱执行

* **Chat-driven Agent 构建**：支持通过自然语言对谈生成与调试智能体，自动提取并沉淀为结构化、可复用的 Skills；
* **内置安全沙箱（DifySandbox）**：为 Code 节点、Tool 节点提供独立的 Python/Shell 执行沙箱，支持安全的数据变形、逻辑判定与本地脚本执行；
* **工作流双向嵌套**：可以在 Workflow 中嵌入 Agent 节点（让智能体在局部自主决策），也可以由 Agent 触发特定 Workflow。

### 4. 企业级内核与合规认证

* **异步非阻塞执行引擎**：数据库写入与长链路调用实现异步化，多分支并行执行耗时由"各分支简单累加"优化为"取决于最长分支"，大幅降低了超时中断率；
* **企业治理资质**：连续两年获得 SOC 2 Type II、ISO 27001:2022 与 GDPR 合规认证，提供完整的审计日志追踪、RBAC 细粒度权限管控。

## 四、 我尝试理解它的定位

以下是我个人调研后的一些理解，不一定准确，仅供参考：

| 维度 | Dify（v1.17+） | Code-First 框架（LangGraph 等） | 纯 SaaS 竞品（Coze / 扣子） |
|:---|:---|:---|:---|
| **我观察到的受众** | 需要跨职能协作的团队（业务 + IT） | 资深后端、AI 全栈工程师 | 个人自媒体、非技术运营 |
| **部署灵活性** | 开源社区版 / 容器私有化 / 多云 | 纯代码库，随业务部署 | 深度绑定平台生态 |
| **调试体验** | 有不错的节点级历史 I/O 检查 UI | 依赖代码断点、LangSmith 等 | 依赖平台日志 |
| **扩展方式** | 插件市场 + MCP + 自定义代码节点 | 纯代码，扩展无上限 | 受限于平台集成库 |
| **工程化协作** | 工作流 DSL 导入导出，Git 差分能力偏弱 | 原生 Git + 单元测试 | 平台内版本管理 |

### 我个人的场景理解

```
                    你的场景更偏向哪边？
                              │
         ┌────────────────────┴────────────────────┐
         ▼                                         ▼
【需要业务与 IT 协同】                      【重度极客 / 算法实验】
• 需要向业务人员可视化呈现流程            • 逻辑高度依赖复杂递归、动态回溯
• 需要开箱即用的 RAG、权限与审计          • 极度依赖 Git 分支与自动化测试
• 需要多模型聚合与 MCP 网关              • 更习惯纯代码，排斥 UI 连线
         │                                         │
         ▼                                         ▼
   Dify 可能比较合适                     LangGraph / 代码自研可能更顺手
```

> 这只是我个人的粗浅理解，实际选型远比这复杂。很多团队可能是混合使用的。

## 五、 商业化与团队现状

这部分是我比较好奇的：它到底赚不赚钱？团队还活着吗？

### 1. 定价体系（公开可查）

| 方案 | 价格 | 说明 |
|:---|:---|:---|
| **Sandbox** | 免费 | 200 message credits/月，1 人，5 个 App |
| **Professional** | $59/月（$590/年） | 5,000 credits/月，3 人，50 App |
| **Team** | $159/月（$1,590/年） | 10,000 credits/月，50 人，200 App |
| **Enterprise** | 定制报价 | SSO/SCIM、私有部署、SLA |

### 2. 收入：未公开，但已盈利

Dify 是未上市公司（Pre-A 轮），没有公开披露过具体收入数字。但从 Forbes（2026-02-24）专访中可以确认一个关键信息：

> "The company built around it employs 100 people, **is profitable** and serves more than 280 enterprise customers."

——**已盈利**，100 人团队。具体营收数字未知。

粗略估算（纯个人推测，无公开依据）：

- 280+ 企业客户中，假设部分走 Enterprise（AWS 标价 $150K/年起），加上 Cloud 订阅收入
- 100 人团队 + 四地办公室，已盈利说明收入能覆盖成本
- 值得注意的是，Dify 官方招聘页写"Over 60% of our codebase is built by LLMs"，研发效率可能远高于传统团队

### 3. 裁员：未发现任何裁员消息

在 Layoffs.fyi 和各类科技裁员追踪中，**没有找到任何 Dify/LangGenius 的裁员记录**。在 2025-2026 年科技行业大规模裁员的背景下，这算是一个正面信号。

### 4. 招聘：仍在招人

Dify 官网（join.dify.ai）截至 2026-09-18 仍有 **4 个开放职位**：

- LTS 后端开发工程师（中国）
- 后端开发实习生（中国）
- UI/UX 设计师（中国）
- 开发者关系实习生（Community Operations）

招聘规模不大，但说明团队在持续运转，没有冻结。

### 5. 开发活跃度：非常活跃

从 GitHub 数据来看：

- **最近版本**：v1.17.1（2026-09-10），v1.15.0（2026-06-25），v1.14.2（2026-05-19）——保持每月至少一个版本的节奏
- **每周活跃度**：约 615 新 Star、132 次 Push
- **Issue 活跃度**：2026-10-13 仍有新 Issue 提交，Maintainer 活跃回复
- **贡献者**：1000+ 人，23.9K Forks

## 六、 调研后的个人看法

1. **Dify 没有消失，只是去了我不太看得到的地方**：从国内极客圈的视角看，它确实"安静"了。但从海外企业市场、日本生态、AWS 渠道来看，它似乎在另一条赛道上跑得挺快；
2. **低代码编排在企业场景里可能还是有它的位置**：虽然 Code-First 是极客圈的审美主流，但现实中很多业务场景需要跨部门协作、可视化审计、权限管控——这些可能不是纯代码框架最擅长的；
3. **100 人团队、已盈利、60%+ 代码由 LLM 生成**——这个组合本身挺有意思。它可能是 AI-native 开发模式的一个早期案例：用 AI 造 AI 工具，小团队撬动大规模；
4. **具体收入数字缺失**是这份调研最大的遗憾。作为未上市公司，这可以理解。但从"已盈利"和 AWS $150K/年的 Enterprise 标价来看，商业模型至少是跑通了的。

> 以上都是个人调研后的理解，难免有偏差。如果你看到的信息与我不同，欢迎指正。
